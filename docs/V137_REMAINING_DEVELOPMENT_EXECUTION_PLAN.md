### 인수표 정량 규칙
- **단계 코드완료율:** Phase 내 소스 연동 확인된 체크 수 / 계획된 체크 수.
- **기기검증 완료율:** 실제 장비 로그·캡처 있는 PASS / 전체 기기 시험. 미실시는 0이 아닌 **NOT RUN** 항목으로 함께 표시.
- **콘텐츠 검수율:** reviewed/published 필드만 집계; 초안을 출처 확인으로 자동 승격 금지.
- **디자인 원안 일치율:** 동일 해상도 원안/현재 화면 비교가 없으면 **미측정**.
- 지표는 새 검증 후에만 갱신. 완료 사실은 테스트 경로·SHA·날짜·인수자를 남긴다.

## 2. 작업 묶음(작은 커밋·중간 CI를 막는 실행 순서)

### Batch A — P0+P1 (즉시, 기능 실패 복구)
1. `docs/V137_TTS_EXECUTION_MATRIX.md` 실행 게이트를 따르고 Web Speech API가 초기 보이스 목록을 비워서 반환할 때의 동작을 수정한다.
2. 음성 엔진 상태를 한 경로로 정리하고, 'AI 여성 음성 준비'를 기본 재생의 필수 단계로 만들지 않는다.
3. 공식 A형/개인 OCR 분리, 정답만·문제+정답·전체, 여성 선호, 1.5배속, 중지·재개·이어듣기·오류를 묶어 테스트한다.
4. ONNX 모델은 라이선스·해시·전송비·Android RAM을 검증한 뒤 저장소/정적 스토리지에 반입. 테스트하지 않은 380MB 모델을 PWA 필수 캐시에 넣지 않는다.
5. **기기 재생 PASS를 확인하지 못한 상태에서는 'TTS 수리 완료'라고 쓰지 않는다.**

### Batch B — P4 콘텐츠 파이프라인(가장 큰 분량)
1. 400문항 공식 원문·정답과 32건 초안 키를 동기화 검증하고, 빠진 368건을 근거 없는 사실 자동 생성 없이 출처 기반 초안으로 채운다.
2. 문항별 질문 논리와 판례·법령의 **시험 당시 기준일** 및 현재법을 분리한다.
3. 각 ①~⑤마다 정오 판단·이유·공식 PDF/검증된 조문·판례 출처·검수자·검수시점을 저장한다.
4. 복수정답 3건·전원정답 8건(10개년 전체 기준)은 '채점상 정답 인정'과 '선지별 참/거짓'을 구분한다.
5. 사용자 공개/기출 분석에 들어가는 원문은 전문가 체크 전까지 초안 마크와 함께 취급한다.

### Batch C — P3/P5
- 공식 800문항의 안정된 문제ID에 태그, 연도, 과목, 출처를 결합해 빈출 통계와 오답 복습을 계산한다.
- 7/30/90/365일 통계, 5×80 혼합 시험, 10×80 통합 실전, 시험 후 약점 다시 풀기를 비교 검산한다.
- 재학습 입력·정답 선택은 원본 기출/개인 기록을 조용히 덮어쓰지 않는다.

### Batch D — P2/P6
- Android Brave S Pen 물리버튼·지우개·필기 후 탭이동 터치 복구, Windows 브라우저 한글 조합·텍스트 부분서식 테스트.
- 17종 차트/검색 인덱스/문항 PDF 판독/음성 동시 사용을 화면별로 테스트한다.
- 이미 구현된 것을 새로 만들지 말고 실패 이슈만 좁혀 보완한다.

### Batch E — P7
- 기능 완료 후 테스트 한 번에 수행. **중간 CI 0, 최종 수동 검증 1회** 원칙.
- 일반 Git push에서는 `vercel.json.git.deploymentEnabled=false` 유지, Actions 워크플로 자동 생성 금지.
- 배포는 사용자가 요청하거나 실기 확인 단계에서 명시적으로 수동 실행한 1회만 처리.
- 설치 EXE/APK/ZIP 아티팩트, 중복 무의미한 빌드 생성 금지.
