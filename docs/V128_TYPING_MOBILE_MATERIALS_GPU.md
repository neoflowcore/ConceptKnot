# ConceptKnot v128 — 타이핑 커서 위치 / 모바일 탭 오탭 / GPU 유휴 / 개인 교재 백업 안전

기준일: 2026-11-06. 복원 기준: GitHub `main` v127 `07c003f7e30d6e37c7a0742ec69b0f7c784e0574`. 이 문서는 GitHub 코드 기준이며 운영 배포·실물 기기 검증과 분리한다.

## 1. 주요 문제 원인과 수정

### P2: 입력 커서의 반응형 위치 불일치
- `assets/ck-typing-layout-v31.js`의 `paintNormal()`과 `paintLetters()`가 입력 문자나 커서 오프셋이 변하지 않은 채 에디터 폭만 바뀐 경우 기존 좌표를 재사용할 수 있었다. 창 크기·모바일 가상 키보드/방향 회전으로 줄바꿈된 뒤 시각적 커서가 실제 삽입 위치와 어긋날 위험이 있었다.
- 현재 `mirror.clientWidth`가 마지막 계산 너비와 달라지면 두 모드 모두 커서 위치·줄 강조 위치를 다시 측정한다. `window.resize` 및 `visualViewport.resize`에서 **타이핑 탭일 때만 한 프레임으로 합쳐 갱신**하며 학습하지 않는 다른 탭의 상시 렌더링·GPU 실행을 만들지 않는다.
- 이 파일은 `index.html`에 스크립트 소스로 직접 내장된다. 원본 JS와 내장 문구를 정확히 동일하게 바꿨고 인라인 스크립트의 문법을 확인했다. 일반/문자만 모드 각각 별도의 입력 초안, 한국어 IME 입력 보존 정책과 키보드 조합은 변경하지 않았다.

### P2: 모바일 탭 오탭 방지
- `ck-nav-drag-v56.js`는 손가락 터치 시작이 특정 탭인데 DOM 재배치로 최종 `click`의 `[data-go]` 대상이 **아예 없어져 로고 또는 빈 레일이 된 경우**, 기존의 `actual &&...` 조건 때문에 잘못된 이동을 막지 못했다.
- 새 보호는 터치가 의도한 탭으로 끝나지 않았으면 클릭을 즉시 취소한다. 의도된 키보드/마우스 클릭과 독립적인 새 터치에서는 이전 오탭 플래그를 제거한다. 가로 스크롤 보존·기존 단일 행 리본을 유지한다.

### P5: 학습 탭의 GPU/애니메이션 유휴
- `ck-gpu-guard-v21.js`의 `visibilitychange`·`pageshow`가 브라우저가 *보이기만* 해도 `focused=true`로 오인해 배경 반복모션을 재개할 수 있었다.
- `document.hasFocus()`가 사용 가능하면 실제 포커스를 확인하고, 포커스를 잃은 창·학습 탭에서는 기존처럼 배경을 정지한다. 장치 특성에 따라 메인 화면의 GPU 사용량 실측은 따로 필요하다.

### P4/P5: 개인 교재 자료실 JSON 및 동시 편집
- `ck84-personal-materials-v1` 기록은 다른 탭이 **revision 숫자는 같게 유지하면서 내용만 바꾼 경우** 기존의 revision 검사만으로 손실 위험이 있었다. 이제 저장 직전 문서 내용도 비교하여 덮어쓰기 대신 차단한다.
- '전체 자료 JSON 백업' 시 저장하지 않은 제목·텍스트·메모, 실행 중 OCR, 손상된 기존 기록, 다른 탭의 동시 변경을 검사한다. 다운로드 전 저장소를 다시 읽어 확인하며 실제 파일 저장 완료를 주장하지 않는다.
- 기존 공식 800문항/정답, 개인 교재/해설의 저장 키·자료를 자동 변경하지 않는다.

## 3. 실제 수행한 검사와 한계

- **격리 V8 모의 실행 PASS:** 두 타이핑 입력 모드에서 폭 변경 시 커서 위치 재측정(2), resize/visualViewport 이벤트 중복 합치기 및 다른 탭에서 유휴(3), 포커스 잃은 브라우저의 메인 애니메이션 정지/복귀(3), 모바일 클릭 대상이 로고로 바뀐 경우 오탭 취소(1), CK84 저장자료 일반/손상/동시변경/미저장 내보내기(6).
- HTML 내장 타이핑과 원본 JS의 일치, 800문항 구조·최종 정답 연결·음성 원문 대응 확인, 인라인 스크립트 컴파일 등은 소스 수준 검증. 신규 `tests/v128-typing-viewport-gpu.test.cjs`와 `tests/v128-materials-data-guards.test.cjs`는 읽기 전용 Node 회귀검증 정의를 제공한다.
- **검증되지 않은 항목:** 실제 `node --test` 전체 실행, Android Brave·Windows Chrome/Edge 실물 브라우저, S Pen 지우개·PDF 2쪽 필기, 한국어 여성 TTS·1.5배속의 실음성·중단·재개, 실제 GPU 사용률, 실제 비행기 모드 및 서비스워커 교체, 공식 법령·판례·해설 검수. 코딩·문서 작성이 끝난 항목을 실기 PASS로 승격하지 않는다.
- 공식 출처 데이터 읽기에서 2016~2025년 800문항·4000선지 구조 오류 0, 전원정답 8, 복수정답 3; 최근 해설 400건 중 초안 32·미작성 368·출처 검수된 선지 0. **구조 점검이지 각 선지의 법적 진위 검수가 아니다.**
- Vercel 운영 READY로 조회된 최근 배포는 v115이며 GitHub 코드 변경은 자동으로 운영에 반영되지 않는다.

## 4. 사용자 수기 실기검증 — 반드시 실제 기기에서 직접

1. **기록 보존 먼저:** 통합 학습기록 JSON, PDF 필기 전용 JSON, OCR 페이지 보관 JSON 및 개인 해설/교재 JSON을 각각 별도로 내보내고 파일을 열어 정상 저장을 확인한다. 캐시 삭제·개인 데이터 초기화 금지.
2. 사용자가 실제 실기검증/배포를 요청한 후 수동 배포했다면 Vercel 운영 SHA가 GitHub 최신 v128 SHA와 일치하는지 확인한다. 현재 운영 v115에서는 v128 새 변경점을 확인할 수 없다.
3. Windows Chrome/Edge에서 타이핑 '일반' 입력, '문자만' 입력을 각각 열고 커서 중간으로 이동한 채 창 너비를 1024→좁게 조절한 다음 커서/줄강조가 입력 위치에 맞는지 확인한다. 한글 IME 조합, Enter/Space, 삭제/되돌리기, 두 모드 초안 왕복 보존도 확인한다.
4. Android Brave 360px에서 가상 키보드를 펼치고 접거나 화면 회전 후 커서 불일치/칠판 글라스 경계 깜빡임을 확인한다. 탭 리본을 오른쪽 끝으로 밀어 '오답 복습'을 누른 뒤 선택 탭이 다른 탭·홈·로고로 잘못 이동하지 않고 스크롤 가로 위치를 유지하는지 확인한다.
5. 메인 화면 애니메이션 실행 중 다른 앱으로 전환/창 blur/뒤로가기/새 탭을 시험한 뒤, 학습 탭 전환에서 배경 GPU 점유가 사라지는지 확인한다. 실제 성능 모니터 계측 필요.
6. 교재·PDF·OCR 개인 자료실에서 새 메모 저장 → 정상 JSON 내려받기·열기, 미저장 입력 내보내기 차단, 두 탭에서 revision은 같고 내용이 다른 변경의 보호, 손상 JSON 원본 비파괴 방어를 확인한다.
7. 설정의 읽기 전용 **오프라인 캐시 11/11** + **현재 활성 SW v128** 확인 후 비행기 모드에서 기출·시험 열기와 재연결 복구 확인. 이전 세대/오프라인 누락은 PASS가 아닌 미확인/FAIL로 표시한다.
8. 80문항·100분·과목별 40점 과락/60점 평균·OMR 저장, 10개년 기출·개인 ①~⑤ 근거, S Pen 물리 지우개·탭 자동 해제, PDF 두 페이지·필기 백업·OCR, 공식 A형 1.5배속 TTS 3모드/일시정지·재개를 직접 재현한다.
9. 설정의 **27개 수기 검증표**를 실제 PASS/FAIL/미확인으로 기록하고 실패 재현 기기·브라우저·문항·단계를 TXT로 보관한다. AI가 자동 PASS를 기록하지 않는다.
