### TTS 핵심 설계 결정

- 기본은 **재생 버튼 하나**. OS에 한국어 음성이 있으면 준비 없이 Web Speech API로 읽기를 시도한다. 사용자에게 여성 모델 초기화 버튼을 강요하지 않는다.
- 별도 **Supertonic 3 ONNX**를 실제 재생 품질·저장 용량·라이선스 확인 후 자체 관리 정적 자산으로 제공한다. 코드 MIT와 모델 OpenRAIL-M은 각각 검토한다. 앱의 기본 SW 핵심 자산에 약 380MB 모델을 강제 포함하지 않는다.
- 최초 방문 기기에 OS 한국어 음성이 없고 AI 모델도 없으면 대용량 모델의 최초 전송이 필요하다. **첫 방문부터 무다운로드 로컬 AI 음성**은 불가능하며, 대량 다운로드를 모바일 데이터에서 무단 실행하지 않는다.
- 기존 AI 버튼·중복 상태/재생 함수는 T2~T5가 실제 통과한 다음 단계적으로 제거한다. 제거 전에 CK76Voice 공개 인터페이스·북마크와 기존 기출 듣기 호출자를 유지한다.
- v137 수정은 **onstart 이벤트 감시**와 실패 구분으로, 실제 스피커에서 한국어 음성이 들렸다는 증거는 아니다. 실제 출력 검증 전에는 TTS 완료를 선언하지 않는다.

- 어떤 TTS 코드도 공식 A형 RECALL_OFFICIAL 문항, 정답, 개인 필기·OCR·타이핑 기록을 변경하지 않는다.

### 5-3. 제품 설계 불변 계약
- DoCut의 목표는 **PPT 호환이 아니라 동작하는 독립 HTML 보고서/포스터**. 편집 원본은 프로젝트 JSON.
- 구성요소는 좌표·크기·레이어·잠금·차트·표·이미지·텍스트와 실제 반응 효과를 분리한다. 원본 HTML은 안전한 구조 추출이 가능한 부분만 재구성하며 범용 임의 JS를 그대로 실행하지 않는다.
- 종이형 정책·금융 보고서는 기본 애니메이션 OFF; 89개 효과는 사용자가 선택했을 때만 켠다.
- 화면은 16:9를 기본으로 하되 무리하게 모든 텍스트 크기를 줄이지 않고 페이지 분할을 제안한다. 개인 데이터와 원문 출처는 비파괴 보존.
- 120장마다 다른 배경만 입히는 20종 반복 생산을 금지. 맥킨지는 주장–근거–대안, BCG는 데이터 시각화, BlackRock은 목표 KPI로 품질 기준을 세운다.

## 8. Action Economy / 릴리스 제한

- 사용자 운영 원칙: 개발·코드 수정·GitHub 업로드는 사전 승인 상태. 같은 승인 질문 반복 금지.
- **중간 GitHub Actions·CI 자동 실행 0회**, 큰 개발 배치 후 최종 검증 1회. 가벼운 로컬 단위/정적 검사는 필요 시 수행하되 불필요한 반복 전체 회귀 금지.
- 일반 Git Push로 Vercel 자동배포가 켜지지 않도록 기존 설정 유지; 임의로 GitHub Actions workflow/설치 빌드를 켜지 않는다.
- EXE·APK·ZIP 등 설치 아티팩트는 실기 검증·설치 요청 직전 **1회만** 생성. DoCut 독립 HTML/JSON의 일반 기능 출력과는 구분한다.
- 배포가 필요한 단계에서만 **수동 Production 배포**, GitHub HEAD/배포 ID/운영 alias를 다시 대조한다. 이 문서 저장만을 위해 앱을 다시 배포하지 않는다.
- 세션 연결 해제 시 해당 저장소의 HEAD와 체크포인트/MD를 먼저 대조해 이어간다. 타 프로젝트로 잘못 이동하거나 기억에 없는 SHA를 임의 적용하지 않는다.
