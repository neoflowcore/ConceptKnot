## 사용자에게 나타나는 실제 수정

### 1. P1 — 공식 A형 음성 낭독 데이터 안전
- **원인:** 기존 `officialAudioEntry()`는 `spokenStore()`의 개인 작성 대조문장 `verified:true`를 공식 문제보다 먼저 반환할 수 있었다. 공식 정답 번호는 원본을 써도 질문과 5개 선지가 사용자가 임의로 수정한 텍스트로 바뀌어 낭독될 위험이 있었다.
- **수정:** 공식 듣기는 **오직 `RECALL_OFFICIAL`의 연도·번호·과목·문항·5선지·중복 없는 정답 ①~⑤**를 읽는다. 개인 작성 문장·가져온 답안이 채점 인정 번호나 공식 낭독을 교체하지 못한다. 개인 작성 데이터 자체는 삭제/수정하지 않는다.
- 기존 '문제 → 정답 지문 듣기' 버튼을 '공식 A형 원문 듣기'로 표기하고, 클릭만으로 별도의 개인 입력을 저장하지 않도록 했다. 저장은 기존 **'이 문항 저장'** 버튼에서 명시적으로 실행한다.
- 실제 공식 2016~2025년 800문항을 샘플 함수에 통과시켜 질문·5선지 일치, 전원정답 8건·복수정답 3건, 일반/복수/전원 채점 인정 유형을 비교했다. *등록 구조 확인이지 시험연도 법령·해설 검증은 아니다.*

### 2. P1 — Web Speech API 긴 문장 오류에서 누락 방지
- **원인:** 기존 기기 음성이 `text-too-long` 오류를 내면 `next()`로 해당 문장을 건너뛰어 연속재생 '완료'로 오인할 수 있었다.
- **수정:** 해당 문장을 최대 4차례 두 덩어리로 다시 나눠 **같은 문장의 첫 부분부터** 재시도한다. 양쪽 문자열을 모두 유지하고, 회차별 북마크 `segmentNumbers`도 함께 확장한다. 재시도 불가능하면 '중단된 문장을 읽지 않았음' 오류로 표시해 성공으로 위장하지 않는다.
- `onend`와 `onerror`가 중복 발생해도 같은 음절을 두 번 넘기지 않도록 utterance별 `settled` 가드를 추가. `voiceschanged` 수신 시 `getVoices()` 예외와 이벤트 API 미지원에도 UI가 중단되지 않도록 방어했다.
- 한국어 여성 음성의 실제 발음·배속·사용 가능 여부는 Android Brave 및 기기의 음성 설정을 이용해 **실제로 들어봐야** 확인할 수 있다. AI ONNX 모델의 첫 다운로드(수백 MB)는 자동 실행하지 않는다.

### 3. P2/P5 — 서비스워커 오프라인 버전 안전
- `CACHE='conceptknot-study-v125-tts-canonical-critical-offline'`.
- 신규 **11개 최소 필수 파일**: index.html, 진단 JS/CSS, 수기검증표 JS, 개인 선지 메모 JS, 개인 해설 편집 JS, 백업 안전성 JS, 공식 기출 로더 JS, 80문항 시험 JS, 2016~2020년 문제 JSON, 2021~2025년 문제 JSON.
- 설치 시작 시 11개 자원을 전부 현재 캐시에 확보해야 `skipWaiting`한다. **하나라도 실패하면 설치를 중단하여 기존에 작동 중인 서비스워커를 새 미완성 세대로 교체하지 않는다.** 전체 기타 자산은 온라인에서 추가 확보하는 best-effort 방식이므로 11개 준비가 모든 기능 오프라인 PASS를 뜻하지는 않는다.
- 이전 버전 index.html에 남은 쿼리는 경로 일치 캐시로 폴백하지만, 다른 캐시 세대에서는 절대 자산을 가져오지 않는다. 서버/캐시 누락 때 503으로 안내한다.
- 실제 `index.html` 스크립트/스타일 3개 경로를 v125와 맞췄다. 기존 대형 HTML의 나머지 내용·키보드/터치 동작은 바꾸지 않는다.

### 4. 사용자 직접 실행하는 읽기 전용 오프라인 진단
- 메뉴: **내 학습 데이터 안전 점검 → 오프라인 필수 파일 준비도 → 이 기기의 오프라인 캐시 검사**.
- 버튼 클릭 시에만 현재 세대 캐시 11개를 확인한다. 미설치, 일부 누락, 캐시 사용 불가, 현재 페이지의 서비스워커 제어 상태를 구분한다.
- 캐시를 삭제하거나 비어 있는 새 캐시를 만들지 않으며, 개인 자료·학습기록을 읽어 원격 전송하지 않는다.
- 해당 검사만으로 이 탭을 제어하는 서비스워커의 **정확한 세대**나 모든 오프라인 기능 작동을 보장하지 않는다.
- 설정 수기검증표 **25→27개**(공식 원문 TTS·긴 문장 무누락 / 오프라인 최소 캐시·연결해제 후 복원)로 확장. 기존 `ck115-manual-device-verification-v1` 형식 및 개인 PASS/FAIL 기록을 그대로 보존한다.

## 수동 배포 후 실제 기기 검증 — 절대 자동 PASS하지 않을 것

1. 기존 브라우저에서 **통합 학습기록 JSON과 PDF 필기·OCR 페이지 자료를 각각 별도 백업**한다. 다운로드가 실제 생성됐는지 확인하고 별도 프로필에서 검증한다.
2. 수동 배포 후 운영 Git SHA가 최신 v125 커밋과 일치하는지 확인한다. **운영이 v115인 상태에서는 신규 v125 버튼이 보이지 않는다.**
3. Android Brave 360px/PC 1024px에서 오른쪽 설정 고정, 스크롤한 탭 선택 후 가로 위치 보존, 다크모드, 탭 전환 시 GPU 유휴 상태를 확인한다.
4. '공식 기출 음성'에서 한 문항의 개인 입력과 원문을 일부러 다르게 작성한 다음, **공식 A형 원문 듣기**에서 개인 문장이 아닌 공식 원문이 재생되는지 실음성으로 확인한다. 버튼을 누르기만 해서 개인 작성란이 저장되지 않아야 한다.
5. 긴 수식/조건 설명 포함 원문 5~10문항을 1.5배속으로 듣고, 문장 누락·반복·끊김 및 이어듣기 북마크를 확인한다. 정답만/문제+정답/전체 선지 세 모드와 한국어 음성 재생·일시정지·재개를 확인한다. **기기 음성에서 `text-too-long` 오류를 재현할 수 없으면 이 세부 항목은 '미확인'**으로 남긴다.
6. 온라인에서 v125 방문 후 안전 점검의 **오프라인 최소 캐시 수동 진단(11/11)**을 확인한다. 인터넷을 끊었다가 페이지를 새로 열어 기본 기능·기출 열기/시험 동작 및 오프라인 누락 안내, 온라인 복귀 후 정상 상태를 확인한다. **서비스워커 설치 도중 연결 끊김**은 원래 기기 데이터를 삭제하지 않는 별도 프로필에서만 시도한다.
7. 80문항·100분 시험을 시작해 일시정지·복귀·OMR 저장·40점 과락/평균 60점을 확인한다. 7/30/90/365일 통계와 TXT 원본 집계 일치도 확인한다.
