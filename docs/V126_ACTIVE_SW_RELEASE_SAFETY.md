# ConceptKnot v126 — 활성 서비스워커 확인 및 읽기 전용 배포 사전점검

기준일: 2026-11-06. 기준 GitHub main: v125 `4e39e0ef77b5d6bd64d30b77911698c5b7dfab39`.

## 이번 코드 범위

- 서비스워커 v126 캐시 세대 `conceptknot-study-v126-active-offline-safety`로 갱신. 기존 필수 11개 파일 설치 실패 시 활성 서비스워커를 교체하지 않는 구조 유지.
- 브라우저의 **실제 제어 중인 SW**로만 전달되는 `CK_SW_VERSION_PING` 메시지에 세대 이름과 필수 파일 수를 답하는 읽기 전용 통신 추가. 사용자 데이터 접근, 네트워크 전송 없음.
- 오프라인 진단은 필수 자산 11개를 **쿼리 버전까지 정확히** 캐시 대조. 이전의 `ignoreSearch:true`는 구버전 자산이 최신으로 오인될 가능성이 있어 제거. 캐시가 11/11이더라도 실제 SW 세대 응답이 v126인지 확인 전에는 준비 완료로 표시하지 않음. 구형/무응답 SW는 보수적으로 미확인.
- JS/CSS/JSON 등 요청이 HTTP 200 HTML 오류/대체 페이지로 돌아온 경우 정상 자산으로 캐시하지 않음. 자산 응답 캐시 쓰기는 `FetchEvent.waitUntil`에 연결, 비동기 저장이 브라우저 조기 종료 때문에 취소될 위험 축소. 요청당 자산 경로 비교를 Set으로 변경. HTML 탐색 캐시도 HTML 타입인지 확인.
- 27개 사용자 수기검증표의 기존 저장 키·개별 항목 ID는 유지하고 오프라인 항목 설명만 활성 SW 확인으로 확장. 다운로드 버튼은 실제 파일 생성 확정이 아니라 다운로드 **요청**으로 정확히 안내.
- 오래된 v100/v102 고정 기대값 때문에 틀리게 실패하던 `scripts/check-release-readonly.cjs`를 v126 캐시·필수 자산·HTML 연결·설정·현재 SW 세대 진단 기준으로 갱신. 수동 실행만 허용.
- 신규 `tests/v126-offline-release-safety.test.cjs`는 격리 모의 실행을 위한 검증 코드(활성 SW 핸드셰이크, HTML 에러 자산 차단, 캐시 생명주기, 엄격 버전 매칭, 배포 차단 설정).

## 사용자 수기 실기검증 필수

1. 먼저 개인 학습기록 JSON 및 별도 PDF 필기·OCR 초안을 백업한 다음 다운로드 파일 생성·열기를 확인.
2. 사용자가 실기 검증을 요청해 최신 버전을 **수동 배포한 뒤**, 실제 Vercel 운영 커밋이 이번 GitHub HEAD와 동일한지 조회.
3. PC 브라우저와 Android Brave에서 온라인 첫 방문 후 서비스워커 제어 상태를 확인. `설정 → 내 학습 데이터 안전 점검 → 오프라인 필수 파일 준비도 → 이 기기의 오프라인 캐시 검사`로 **11/11 + v126 활성 SW**를 동시에 확인. 구형 SW는 새로고침 후 재검사.
4. 네트워크 연결을 끊고 기출 열기·80문항 모의고사 기본 동작, 누락 자산 503 메시지, 재연결 복구를 직접 확인. 캐시 삭제/개인 기록 초기화 금지.
5. 공식 2016~2025 A형 낭독과 사용자 작성 텍스트 분리·긴 문장·한국어 여성 음성/1.5배속/중단·재개를 실제 스피커로 확인.
6. 모바일 가로 탭 위치, 설정 오른쪽 고정, 다크모드, 시험 80문항/100분·과락, S Pen 지우개·PDF 두 페이지 획·OCR 페이지·편집 메모 저장을 직접 확인.
7. 설정의 27개 실기검증표는 항목별 PASS/FAIL/미확인 및 기기·문항·재현 순서를 **사용자가 직접** 기록하고 TXT를 보존.
