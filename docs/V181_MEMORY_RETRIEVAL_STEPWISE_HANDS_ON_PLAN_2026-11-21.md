## 1. 학습 흐름과 사용자 경험

`전체 개념 훑기(프라이밍) → 핵심 기준 개념(앵커) → 자신의 말로 요약 → 설명 없이 인출 → 기출 피드백 → 일정 간격 뒤 재인출`

사용자 화면은 차트 **하나**를 중심으로 유지한다. 차트 아래의 기존 `쉬운 설명 → 심화 설명 → 문제` 3단계 경험을 보존하되, 기억 학습 모드에서만 단계별 노출을 제어한다. 설명이나 문제를 처음부터 전부 늘어놓지 않는다. 학습 검증 도구의 로그는 **설정 → 검증 자료**로 보내고 일반 학습 화면에는 노출하지 않는다.

| 단계 | 하나의 개발 목표 | 사용자 직접 확인(실기) | 통과 조건 | 현재 |
|---|---|---|---|---|
| M0. 기준선 | 소스·기존 인출/복습/도형 엔진·저장키 조사, 테스트 샘플 고정 | 현재 차트 드래그·초기화·설명·문제·기록 정상 작동 확인 | 기존 기능·개인 기록 손상 0건, 검사표 작성 | NOT_STARTED |

**진행 순서:** M0→M1→M2→M3→M4→M5→M6→M7. M1은 인출 학습의 효과를 가장 빠르게 시험할 최소 기능으로 먼저 배치한다. M0/M1의 사용자 실기 결과가 PASS일 때만 M2에 진입한다. 해당 단계 수정 시 동일 단계만 재검증하고, 마지막에 통합 회귀검사를 한 번 수행한다.

## 3. 첫 실기 대상 M1 상세 사양

1. 기존 **단일 차트**에 `기억 테스트` 진입 버튼을 추가한다(실제 개발 단계에서만).
2. 시험 중 설명·정답·이전 상태의 시각적 힌트를 가리고, 문제와 차트만 제시한다. 접근성 라벨·숨은 DOM 텍스트로도 정답을 미리 노출하지 않는다.
3. 질문 예시: `정상재의 소득이 증가하면 수요곡선은 어떻게 변하는가?` 사용자는 **곡선 이동 방향을 예측**하거나 선택지로 먼저 답한다.
4. `정답 확인` 시 기존 차트 E₀/E₁ 중첩 및 쉬운 설명·심화 설명·관련 문제로 연결한다. `틀린 이유`는 `가격 변화 / 소득 변화 / 기타`처럼 분류하되 실제 근거와 혼동하지 않는다.
5. 학습자가 `맞혔다 / 헷갈렸다 / 틀렸다`를 기록할 수 있다. 입력하지 않은 경우 오답으로 자동 간주하지 않는다.
6. `다시 풀기`는 정답·해설 상태를 완전히 숨기고 초기 조건으로 돌아간다. 기존 차트 조작의 Undo/초기화 기능은 보존한다.
7. 실제 S펜/손가락 드래그 시 곡선 손잡이 위에서만 차트가 반응하며, 빈 곳에서는 스크롤한다. 좁은 화면은 차트 하나와 위아래 배치만 사용한다.

## 4. 기술·데이터 경계

- **재사용 우선 조사:** `assets/ck-study-recall-v83.js`, 기존 학습 일정·간격 반복 엔진, `assets/ck-graph-compact-v178.js`, `assets/ck-study-charts-v79.js` 및 관련 Android 이관 코드를 실제 소스 기준으로 확인한다. 파일명 존재만으로 현재 Android에 기능이 구현됐다고 인정하지 않는다.
- **Android 구현:** Kotlin/Compose 쪽 기존 A0~A5 경계를 유지하고, 학습 단계·차트 조작 상태·인출 결과·반복 일정은 UI와 분리된 상태 모델로 설계한다. 웹 코드를 무조건 WebView로 감싸지 않는다.
- **저장:** `conceptId`, `diagramId`, `attemptedAt`, `prediction`, `selfRating`, `sourceStatus`, `nextReviewAt`, `schemaVersion` 등 최소 필드부터 정의한다. 원본 문항·정답과 사용자 인출 이력을 별도 저장. 로컬 데이터 내보내기/가져오기와 이전 버전 호환을 확인한다.
- **복습 알고리즘:** 최초 후보 1·3·7일은 **검증 전 기본값**일 뿐 고정 최적값이나 과학적 보장으로 표시하지 않는다. 복습 지연·오답·자기평가에 따라 조정하고, 날짜 계산은 Asia/Seoul 기준으로 검사한다.
- **학습 성과 검증:** 구현 동작 PASS와 별도로 즉시/다음날/7일 지연 인출 정확도, 재도전 수, 오류 유형, 소요 시간을 기록할 수 있도록 한다. 비교 실험 없이 '암기력 향상 보장'이라고 표시하지 않는다.

## 5. 공통 품질 게이트 및 증거

단계별로 반드시 `요구사항 ↔ 수정 코드 ↔ 화면 상태 ↔ 자동 검사 ↔ 실제 기기 실기`를 한 줄로 대응한다.

- **자동 검사:** 상태 전이, 정답 선노출, 차트 전후 정합성, 기출 원본 불변, 데이터 스키마·백업 호환. 실행한 명령·결과·커밋 SHA 기록.
- **브라우저 시뮬레이션:** 좁은 폭 360/390px과 데스크톱 폭, 가로 넘침·버튼/텍스트 잘림 확인. 시뮬레이션 PASS를 실제 Android S펜 PASS로 바꾸지 않는다.
- **실기:** 사용자의 Android 기기에서 터치·S펜·스크롤·오프라인·종료/재실행·데이터 보존 확인. 못 해본 항목은 **NOT_RUN**, 실패는 **FAIL**, 증거가 있는 항목만 **PASS**.
- **진입 게이트:** 해당 단계의 필수 시나리오 100% PASS, 원본 데이터 회귀 0건, 사용자 검증 후 다음 단계. 실패한 단계는 수정하고 다시 실기한다.
- **릴리스:** GitHub Actions 자동 실행·중복 아티팩트 생성 금지. 기능 묶음 완료 후 최종 통합 검사 1회. APK 생성은 실기 직전 필요할 때만. 웹 운영 배포는 명시적으로 재개된 범위에서만 수동 실행.
