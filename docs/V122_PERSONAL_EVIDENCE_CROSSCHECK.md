# ConceptKnot v122 — 개인 근거 교차점검과 원본 백업 안전 보강

작성 기준: 2026-11-05, GitHub main v121 `ea17b3c61415610dd58da654aa57239e37b194c0`.

## 문제와 수정

- **기존 오류:** v112에서 개인 해설 초안을 2016~2025년 800문항으로 확장했으나, v121의 읽기 전용 안전 진단기 한 곳은 아직 최대 400개/2021~2025년만 유효하다고 평가했다. 기존 정상적인 2016~2020년 개인 기록에 거짓 손상 경고가 날 수 있었다.
- **수정:** 진단도 800건/2016~2025년 ID를 허용하고, 가능할 때 CK86 안전 복원 검증기를 재사용한다. 공식 답안·해설·사용자 자료를 자동 변경하지 않는다.
- **원본 복구용 다운로드:** 12종 원본을 두 번 읽어 같은지 대조한다. 로컬 저장소 읽기 오류나 도중 변경이 발생하면 백업 생성 요청을 중단한다. 일부 오류를 `null`로 조용히 치환해 불완전한 백업을 완전한 파일처럼 내보내지 않는다. 외부 저장소 동시성은 완전한 데이터베이스 트랜잭션이 아니므로 실제 복원용 JSON과 PDF 필기 백업은 별도로 보존할 것.

## 신규 읽기 전용 기능

`내 학습 데이터 안전 점검 → 800문항 · 4,000선지 개인 근거 교차점검`

1. 사용자가 누른 경우에만 10개년 공식 800문항 로딩 여부 및 개인 기록 CK83(선지별 판단/근거)과 CK80(개인 해설 초안)을 별도로 읽는다.
2. 연도별 두 저장소의 출처 건수, 양쪽 모두 출처 없는 선지, 양쪽에서 `true/false` 판단이 다른 선지, 같은 선지의 개인 출처 텍스트 차이를 표시한다.
3. 전원정답/복수정답은 채점 인정 유형으로만 표시한다. 채점 인정 번호를 선지 참/거짓으로 오인하지 않는다.
4. '개인 입력 5/5'는 한 저장소에 판단·근거·출처를 작성한 수치를 뜻한다. **공식 원문·법령·판례 검증이나 정답 진위·게시 승인으로 사용하지 않는다.**
5. 연도와 유형 필터, 16문항 페이지 탐색, 해당 문항/근거 열기, 800문항 CSV 다운로드. CSV 수식 인젝션 방지용 기존 `csvCell` 재사용. HTML 삽입 가능한 개인 텍스트를 카드에 표시하지 않는다.
6. 미저장 개인 입력, 손상/교차탭 충돌 또는 공식 기출 부분 로딩 시 내보내기 중단. 변경 이벤트 발생 시 저장된 교차 점검 결과는 무효화된다.

## 수동 배포 후 실기 점검

1. 기존 학습 통합 JSON과 PDF 필기를 각각 원본으로 보관. 별도 브라우저 프로필에서 테스트.
2. 운영 배포 SHA를 GitHub v122와 비교(오래된 v115 배포라면 이 기능은 보이지 않는다).
3. `안전 점검`에서 개인 2016년 문항 1개를 CK80에 저장해 **정상 형식**인지 확인. 백업이 이전과 동일한지 확인.
4. 교차 점검 실행 후 800/800, 4,000선지, 연도별 수치, 판단 차이·출처 차이·누락 필터, 이전/다음과 CSV를 확인.
5. 같은 문항의 CK83과 CK80에 서로 다른 개인 판단을 고의로 넣고 재검사하여 판정 불일치 1건이 증가하는지 확인. 테스트 뒤 원본 JSON 복원.
6. 시험, TTS 1.5배속·3모드, S Pen 물리 버튼, 2쪽 PDF 필기, OCR 페이지별 보관함, 모바일 탭 위치, GPU 유휴상태를 수기로 확인. 설정의 21개 수기검증표에 직접 PASS/FAIL을 기록.
