# ConceptKnot v127 — 신규 OCR 초기화 복구·오프라인 세대 무결성·개인 백업 안전성

기준일: 2026-11-06. 코드 복원 기준: `main` v126 `e6b0ff5c592471fd1ea07c11cc987de611a619cf`.

## 확인된 원인과 수정

### 1. P2/P5: 신규 사용자의 OCR 도구 초기화 오류 복구
- 오류 경로: `assets/ck-ocr-v118.js`에서 `let draft=read()`를 실행한 뒤 `const empty=...`를 선언했다. 해당 브라우저에 초안이 없는 초기 호출 `read()`가 아직 초기화되지 않은 `empty()`를 실행해 `ReferenceError`가 발생할 수 있었다.
- 수정: `empty()`를 호이스팅되는 함수 선언으로 변경. 신규 사용자의 빈 저장소·손상 데이터 보호 경로에서 동일 기본 객체 생성 가능.
- 다른 탭에서 페이지 보관함이 바뀌었거나 현재 페이지에 미저장 편집이 남은 경우 **보관 페이지 전체 TXT**를 오래된 상태로 내보내지 않도록 차단. 기존 저장값 삭제·자동 변형 없음.

### 2. P5: 오프라인 자산이 진짜 코드인지 확인
- `CACHE=conceptknot-study-v127-integrity-guarded-offline`.
- `cache.addAll(CRITICAL)` 성공은 HTTP 상태만 보장하고 콘텐츠 종류를 검증하지 않는다. HTTP 200으로 HTML 오류 화면이 스크립트·JSON 대신 수신돼도 새 SW가 잘못 활성화될 수 있었다.
- 설치 과정에서 기존 **11개 필수 파일의 캐시 응답 상태와 콘텐츠 유형을 재확인**한다. `.js/.json/.css` 대신 `text/html`, `index.html` 대신 다른 명확한 타입이 있으면 설치를 실패 처리하고 이전 정상 SW를 유지한다. 실패한 현재 세대 캐시 항목만 정리한다.
- `cachedCurrent`는 `?v=` 등 쿼리 있는 요청을 **정확히 같은 버전**으로만 반환한다. 무쿼리 경로의 이전 호환 매칭은 유지하되 `?v=126` 파일로 `?v=127` 요청을 대신하지 않는다.
- 사용자가 직접 호출하는 캐시 진단도 정확한 URL+쿼리뿐 아니라 MIME을 비교한다. **11/11 및 현재 제어 중인 v127 서비스워커 확인**을 따로 충족해야 준비 상태로 표시한다.

### 3. P4/P5: 개인 해설·OCR 내보내기 무누락
- `ck80-explain-drafts-v1` 개인 JSON 내보내기 도중 저장하지 않은 편집이 있으면 차단한다. 다른 탭이 이미 스냅샷을 바꿨거나 파일 생성 직전에 다시 변경된 경우에도 중단하고 기존 자료를 유지한다.
- 파일 생성/브라우저 다운로드 요청과 실제 파일 저장 성공을 구분해 알린다. 사용자에게 내보낸 JSON 확인을 요청한다.
- OCR 페이지 TXT는 페이지 저장소를 내보내기 전후 두 번 읽어 변경 여부를 확인한다. 다른 탭/저장 오류/미보관 현재 OCR 편집이 있을 때 오해를 낳는 TXT를 만들지 않는다. 손상 원본 JSON 다운로드 경로는 기존처럼 보존한다.

### 4. 브라우저 캐시 갱신과 테스트
- 변경된 네 JavaScript 자산의 쿼리 버전을 HTML·SW 필수/선택 자산목록·읽기 전용 진단과 일치하게 모두 `?v=127`로 조정: `ck-data-diagnostics-v88.js`, `ck-study-editor-v80.js`, `ck-manual-qa-v115.js`, `ck-ocr-v118.js`.
- 과거 v114·v115·v118·v120·v124·v125·v126 검사에서 이전 캐시 버전을 고정하던 기대값을 실제 v127 기준으로 갱신한다. 레거시 저장 키, 공식 정답 800개, 최근 400개 해설 JSON 스키마는 바꾸지 않는다.
- 수기 QA는 기존 27개 항목 ID와 저장 키를 유지하며 활성 SW v127 확인 문구만 반영한다.
- `scripts/check-release-readonly.cjs`는 수동 실행용. 오프라인 필수 파일 타입 검증·잘못된 쿼리 버전 폴백 방지·자동배포 비활성 조건을 확인한다.
- 새로운 `tests/v127-personal-offline-guards.test.cjs`: 필수 자산 거짓 MIME, 실패한 업데이트 세대 보존, 구형 쿼리 폴백, MIME 캐시 진단, 해설 편집/다른 탭 백업, 신규 OCR 시작, OCR 보관함 충돌 사례 등 10개의 Node 테스트 정의.

## 운영 배포 후 수기 실기검증 — 자동 PASS 금지

1. 사용자 브라우저의 **통합 학습기록 JSON, PDF 필기 JSON, OCR 페이지 초안**을 별도로 백업하고 다운로드된 파일을 열어 본다. 다른 프로필이나 임시 사용자로 시험한다.
2. 사용자가 실기검증을 요청한 다음 수동으로 v127을 배포한 경우 Vercel 연결 SHA가 실제 GitHub 커밋과 일치하는지 확인한다. 구버전 v115가 운영 중이면 v127 기능은 나타나지 않는다.
3. 빈 브라우저 프로필에서 처음 OCR 페이지를 열어 오류 없이 기본 UI가 나타나는지 확인한다. OCR을 한 번도 사용하지 않은 상태, 정상 초안 1개, 손상 초안 1개를 서로 독립적으로 시험한다.
4. 오프라인 점검에서 **필수 11/11**과 **현재 활성 SW v127**을 동시에 확인한다. 연결을 끊고 HTML·스크립트·기출·시험 화면을 연 후 재연결한다. 구형 캐시 파일을 `?v=127`로 잘못 반환하지 않아야 한다.
5. CK80 해설 작성 화면에서 한 글자를 고친 후 저장 전 JSON 내보내기를 눌러 차단되는지 확인한다. 저장 후 내보내기를 수행하고 파일을 열어 실제 초안이 포함됐는지 확인한다. 두 탭에서 서로 다르게 편집 시 덮어쓰기 차단을 확인한다.
6. OCR 페이지별 보관함을 두 탭에서 변경한 후 이전 탭의 '전체 TXT'가 잘못된 최신 목록으로 표시되지 않는지 확인한다. 현재 초안을 보관한 뒤 정상 내보내기를 비교한다.
7. Android Brave에서 오른쪽 설정 메뉴 고정, 가로 탭 스크롤 유지, 실물 펜 버튼 지우개, PDF 두 페이지 필기 및 복원, 공식 A형 음성·긴 문장·1.5배속, 80문항 100분 모의고사, 오답/통계/다크모드를 확인한다.
8. 설정의 **27개 수기 실기검증표**에서 PASS/FAIL/미확인을 직접 표시하고 기기·브라우저·문항번호·실패 재현 메모를 TXT로 보관한다.
