# ConceptKnot v115 — 모바일 탭 실행 경로 복원 · 데이터 보존 · 기기 수기검증표

개발 기준선: `main` **v114** `bbe5351a27e59857c9acc27c8d73e5ce21832286`. 동일 프로젝트 기록과 GitHub·Vercel 최신 상태를 조회해 대조한 뒤 착수.

> **정적/모의 테스트 통과와 실기 PASS는 다릅니다.** Android Brave, 갤럭시 S펜 물리 버튼, 한국어 TTS 실제 출력, PDF 실물 필기, GPU 사용량은 직접 기기에서 확인해야 합니다. 설치파일·Actions 아티팩트 생성 없음.

## 실제 확인한 원인

- 기존 `assets/ck-nav-drag-v56.js`는 저장소와 `sw.js` 캐시에 존재했지만 **v114 `index.html`에서 호출되지 않음**. 따라서 모바일 가로 스크롤·선택 위치 보정 코드가 실화면에서 실행되지 않을 수 있었음.
- `boardFrame`이 재생성한 최초 DOM에는 `ck105-anchored-tools`, `ck4-unified` 클래스가 없어, 후속 MutationObserver가 붙일 때까지 헤더·스크롤 너비가 재측정될 수 있었음.
- 80문항 시험 로컬 저장은 `revision`만 비교하므로 다중 탭의 같은 revision 수정/삭제가 누락될 여지가 있었음.
- CK83 개념/선지 메모에서 비동기 taxonomy 로딩 완료 후 편집 DOM을 교체할 가능성과, 연도 변경 확인을 취소했을 때 화면의 선택값이 어긋날 수 있는 경로를 발견.
- `changeView`가 저장 실패·취소 전에도 S펜 종료/화면 상태를 변경할 수 있었고, 이미 기출 탭일 때 다른 공식 문제로 열어도 렌더가 생략되는 경로가 있었음.

## v115 코드 변경

1. **내비게이션 연결 및 모바일 입력**: `index.html`에서 `ck-nav-drag-v56.js?v=115` 명시 로드. 한 줄 탭 스타일 중복 삽입 방지. 첫 HTML부터 오른쪽 독립 도구·가로 탭 구조로 렌더. 터치/마우스 드래그의 스크롤 위치 보존, 이동 중 클릭 차단, 가로 이동 후 다른 메뉴로 오탭 차단, 연속 스와이프 이후 빠른 새로운 탭 선택 허용. 필요할 때만 1회 애니메이션 프레임 사용; 상시 루프 없음.
2. **화면 이동 원자성**: `changeView`가 CK78 풀이 메모, CK80 해설, CK83 개인 근거, CK115 수기검증표의 미저장 상태를 확인. 저장이 실패하면 화면 및 펜 모드를 유지하고 사용자에게 알림. 원문 문항 직행 링크는 `CK76Study.openQuestion` 단일 경로로 통일해 과목 자동 맞춤/기출 탭 내부 재렌더/중복 저장 최소화.
3. **CK83 메모 수명**: taxonomy 비동기 완료가 작성 중인 UI를 교체하지 않음. 개념 연결 저장 이후 대기 중인 모달을 안전하게 띄우며, 연도/번호 변경 취소 시 선택 UI를 이전 문항으로 되돌리고 작성 중인 근거 필드를 보존.
4. **80문항/100분 시험 안전 저장**: `ck-full-exam-v82.js`에서 저장소 원문 문자열 비교를 추가해 동일 revision 타 탭 변경과 로컬키 삭제를 감지하고 덮어쓰기 차단. 100분/과목별 40점 과락/평균 60점 채점 엔진 및 이전 시험 데이터는 변경하지 않음.
5. **기기 수기검증표**: 설정 화면에 15항목 `CK115QA` 삽입. 각 항목의 PASS/FAIL/미확인/해당 없음 및 재현 메모를 현재 브라우저에만 저장. 사용자 클릭으로만 기기 환경 읽기(화면폭, 탭 위치, 음성 상태, PDF 상태 등). TXT 출력, QA 상태 초기화, 여러 탭 저장충돌 보호. 자동 PASS 없음. 수기검증 데이터는 `CK79Study.exportBackup`의 통합 JSON에 포함되며 `CK86Integrity`가 엄격한 QA 전용 스키마·50k 상한으로 검증 후 복원.
6. **PDF 캐시 정합성**: v114 페이지의 `ck-pdf-workspace-v15.js?v=60` 요청과 SW의 v59/v113 중복 캐시를 조사해 v115 요청으로 통일. SW HOT/ASSETS의 PDF 모듈을 버전 일치한 2참조로 줄이고 정적 응답의 `no-cache` 헤더를 추가. S Pen 실물 필기 검증은 여전히 별도.
7. **캐시/비용 제약**: `sw.js` v115로 업데이트해 nav 모듈·QA 모듈/스타일·새 시험/복원 코드를 오프라인 캐시. 기존 중복 무버전 nav 항목 제거. `vercel.json.git.deploymentEnabled=false` 고정, `.github/workflows` 생성 없음, 일반 Push로 자동 Vercel/Actions 빌드 불가, EXE/APK/ZIP 생성 없음.

## 데이터/진척 근거

기존 v114 직접 데이터 구조검사 기록: 2016~2025 **800/800문항**(연도당 학개론 40, 민법 40), 전원정답 인정 8, 복수정답 인정 3, 최근 해설 400개 중 미작성 368/초안 32/공식 sourceChecked 0. **v115에서는 공식 JSON·답안·해설 원문 수정 없음**. 이는 구조적 등록이지 외부 법령·판례 검증 완료가 아님.

마지막 운영 측정 체크포인트: **19/30=63%**, P0 80%, P1 80%, P2 80%, P3 60%, P4 40%, P5 40%. 현재 v115 전체 기능 완성률, 실제 기기 PASS 비율, 디자인 초안 일치율은 **재측정 전**이며 임의 추정 없음.

## 반드시 수기 실기검증 — 설정 화면에서 검증표 직접 기록

1. 기존 학습기록을 먼저 **`내 데이터 → 내 학습 데이터 다운로드`**로 JSON 백업. 다운로드 파일 보관 전 초기화·사이트 데이터 삭제 금지. 검증표에도 데이터 백업 성공 여부를 수기로 기입.
2. PC와 Android Brave에서 v115 페이지 새로고침. 360/420/768/1024/1600px 폭으로 확인하면서 오른쪽 설정이 끝에 고정되는지, 상단 탭/로고가 한 행이며 겹치지 않는지 점검.
3. 모바일에서 탭을 오른쪽으로 스와이프한 뒤 **오답 복습 → 학습 계획 → 정리본** 순서로 빠르게 터치. 화면 본문과 탭 강조가 일치하는지, 가로 스크롤이 0으로 돌아오지 않는지, 스와이프가 잘못된 홈 클릭으로 처리되지 않는지 확인.
4. 원문·차트 등에서 2024년 **56번 민법** 링크를 열어 과목이 정확히 전환되는지, 이미 기출 탭인 상태에서 다른 문항을 열면 본문이 즉시 갱신되는지 검사.
5. CK78 풀이 메모/CK80 개인 해설/CK83 ①~⑤ 근거 작성 중 종료·다른 탭·ESC를 누르면 미저장 내용이 보호되는지 확인. 2016~2020년 원문 비동기 로딩 중 다른 문항을 선택했을 때 이전 응답으로 덮이지 않아야 함.
6. 실제 80문항·100분 OMR 기능의 연도별 학개론/민법 40문항, 40점 미만 과락/평균 60점 기준, 100분 만료, 미응답·복수정답·전원정답 처리를 수기 확인. 별도 브라우저 탭에서 답을 바꾸면 기존 기록을 덮지 않는지 확인(테스트 전 JSON 백업).
7. 한국어 TTS 1.5배속/3모드/정지·일시정지·재생과 실제 40문항 소리. PDF 원본 두 페이지 펼쳐보기, 오른쪽 S펜 필기, 물리 버튼 지우개, 칠판 탭 이동 후 손가락 터치 회복을 실제 기기에서 확인.
8. 다크모드 점 배경, 상단/본문 대비, 학습 탭 진입 시 배경 GPU 렌더 중지와 실제 소비량을 확인. 자동으로 PASS로 표시하지 않음.
9. **설정 → 실기검증표 v115**에서 항목별 PASS/FAIL/미확인과 실패 재현 메모를 저장. `수기 검증 TXT 저장`으로 결과 보관하고 `내 학습 데이터 다운로드`로 QA 포함 통합 JSON 백업. 다른 브라우저에서 복원 성공 여부는 백업 후 별도 확인.
10. 실패 사례에는 기기/Brave 버전/화면 폭/문항 ID/정확한 재현 순서 및 가능하면 화면을 첨부. 코드 테스트 PASS와 수기 PASS를 혼동하지 말 것.
