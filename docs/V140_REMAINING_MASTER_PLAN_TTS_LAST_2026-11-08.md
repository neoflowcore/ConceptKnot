# ConceptKnot — v140 이후 잔여 개발 실행계획서 v1.0
**작성·재개 기준: 2026년 11월 8일 / 다음 채팅 개발 착수용**

> 이 문서는 ConceptKnot 전용 단일 재개 기준서다. 과거 통합 계획서의 DoCut 작업은 **일절 소환하거나 개발하지 않는다**. 사용자 실기에서 AI TTS가 **중간에 끊기고 느리다**고 보고되었으므로, AI 음성 모델/캐시 대규모 개선을 **비음성 핵심 기능 이후 마지막 단계**로 옮긴다. 기존 기기 TTS는 필요 시 임시 사용하되, 음성 품질 문제가 해결되었다고 주장하지 않는다.
>
> **이번 대화에서는 계획서만 작성·GitHub 보관한다.** 기능 소스 수정·운영 재배포·설치 파일 생성은 다음 채팅에서 이 계획서를 읽고 진행한다.

## 3. Batch A — P0 + P2, 다음 채팅에서 가장 먼저 착수

**A0. 기준선·데이터 보호**
- 최신 GitHub main / 변경 파일 / Vercel 연결 상태 / 자동배포 차단을 재확인.
- 기존 localStorage 키, 공식 A형 원문/정답, 개인 OCR/필기/타이핑/해설 초안/시험 기록의 스키마를 먼저 읽는다.
- 개인 데이터 복구는 사용자의 실제 브라우저 데이터를 임의로 지우지 않고 **격리된 프로필**에서만 재현. 원문 백업과 복원 이후 해시·키 수·문항 ID 비교.
- PWA 필수 캐시 11개·선택 캐시(혼합/약점)·서비스워커 세대를 서로 혼동하지 않는다. 강제 캐시 삭제·전체 Storage 초기화 금지.

**A1. 한글 타이핑**
- 두 입력 모드(문자만·전체 원문)에서 ㅂ→버→법 같은 IME 조합과 선택·삭제·중간 커서 이동·Enter/Space 토글 반복 재현.
- 커서 불일치, 오타 강조 완화, 줄 강조, 한글 조합 중 중복·누락·포커스 이탈 수정.
- 타이핑 입력 때 칠판 왼쪽 글라스 경계가 깜빡이는 현상은 불필요한 전체 리렌더/레이아웃 변경/관찰자 이벤트 원인을 추적하고 최소 DOM 갱신으로 해결.
- 기존 타이핑 단축키와 시험용 Ctrl+방향키 충돌 금지. 모바일 입력창/IME/S Pen 포커스에서는 시험 키보드 핸들러 실행 금지.

**A2. 칠판·PDF S Pen**
- 좌1/3 타이핑·우2/3 칠판, 칠판 이동형 모달, 지우개 버튼/물리 펜 버튼, S Pen OFF/탭 이동 자동 해제.
- 칠판 S Pen을 끄지 않고 메뉴·다른 탭으로 이동해도 손가락 터치 정상 복원.
- 필기 PDF 2페이지(이상), 페이지 교체, 펜 획 유지, 백업·복원, 장치 미지원 물리버튼은 조건부 안내.
- 얇은 글라스 경계와 모바일 탭 위치·우측 고정 설정 UI·다크모드 외부 배경을 회귀 점검.

**A 완료:** 재현 가능한 입력/터치 오류의 코드 수정 + 격리 테스트 PASS. Android S Pen 실기는 사용자 확인 전 NOT_RUN.

## 4. Batch B — P3 시험·기출, P5 약점 1차

**B1. 기존 UI 유지**
- 모의고사 / 기출혼합 / 공식 통합 실전을 **3개 대분류 아이콘**으로 선택하고, 선택 후 1~5세트 또는 연도 버튼. 기존 문제 왼쪽 + OMR 오른쪽의 2열 UI 보존.
- 개인 약점 분석·다시 풀기는 시험 영역 아래에 유지하고, 단일 실전 유형 전환 시 다른 시험의 답안을 덮어쓰지 않는다.
- 모바일 탭 클릭 시 첫 탭으로 튀거나 가로 스크롤이 초기화되는지 재검증.

**B2. 채점·시간·키보드**
- 80문항(학개론 40, 민법 40), 100분, 일시정지/재개/시간 만료/제출/새로고침 복귀, 40점 과락·평균 60점 임계 검산.
- 공식 특수정답의 복수 인정·전원정답 인정과 미응답을 분리. 정답 인정은 법리 진위의 확정이 아님.
- 숫자키 1~5(상단/넘패드), Ctrl+←/→, 첫·마지막 문제 경계, 일시정지·제출 후 입력 차단. 입력창·IME·모달에서는 비활성.
- v140 공식 실전의 일시정지 보류 표시 잠금과 저장 결과가 실제 화면에서도 동일하게 동작하는지 검증.
- 다른 탭에서 답안 변경 시 오래된 기록의 저장/TXT 출력을 차단.

**B3. 개인약점**
- CK82 10개 연도·CK129 5세트의 제출 기록을 정답·선지·제출 시간·중복 제거 규칙에 따라 통합하고, 기존 **오답×5 + 미응답×3 + 보류×1** 우선순위를 검산.
- 기록 0건·한쪽만 제출·두쪽 다 제출·한쪽 진행 중·손상 기록·동일 ID 재출제 경우 모두 확인.
- 다시 풀기의 개인 선택은 공식 OMR/성적/정답 키를 수정하지 않는다. 2016~2020/2021~2025 근거 화면 연동을 확인.
- 아직 검증되지 않은 법리 해설을 자동 정답 근거처럼 노출하지 않는다.

**B 완료:** CK82/CK129 자료·타이머·채점/이동/복습의 경계 테스트를 묶어서 PASS. 실제 OS/브라우저 검증은 별도.

## 5. Batch C — P4 해설·출처 검수 (대량 병행 트랙)

**현재 실제 데이터(2026-11-08 v140 기준):** 2021~2025 400문항 / 초안 32(2024년 11·2025년 21) / 미작성 368 / 해설 검수 0 / 선지별 출처 감수 0/2,000. 도구가 생성한 '검토 패킷 400건'은 해설 400건 작성 완료를 의미하지 않는다.

**C1. 작업 도구** 
- 기존 scripts/build-explanation-review-packets-v140.cjs 활용: --year, --status, --limit, --offset, --json. 공식 문항 ID/5선지/인정 정답/기존 초안/원문 출처/검수 빈칸에 연결.
- 실제 공개 Q-Net PDF, 당시 법령·시행일, 판례·판시사항 및 최신법 변경사항을 문항별 독립 구분해 기록.
- 출처 자료가 없는 경우 '보류/조사 필요'로 두며, 개인 초안을 verified/published로 자동 승격하지 않는다.
- 법령 검토가 필요한 ①~⑤는 정오 판정·핵심 이유·조문/판례·시험 기준일·출처 링크·검수일·검수자 각각 기록한다.

**C2. 실행 범위**
1. 특수정답/기존 초안 32건 우선 출처 검사와 원문 대조.
2. 나머지 368건 초안은 출처를 확보한 건부터 생산하고 검수 대기열에 분리 저장.
3. 400문항과 2,000선지 출처·근거·승인 상태 누적 계산.
4. 이후 2016~2020 400문항 해설은 별도 장기 범위로 분리해 출처·인력·시간을 재산정한다.

**C 완료:** 공개 가능 상태는 전문가 승인과 재현 가능한 출처 기록이 있는 문항에만 부여. '초안 작성률', '법리 검수율', '선지 검수율' 세 수치를 분리 보고.

## 7. Batch E — P0/P7 최종 통합·수기검증·수동 배포

### 수기검증 범위 (반드시 크게 안내)
1. **Windows Brave**: 공식/혼합 80문항·100분·1~5/Ctrl 좌우·제출·복습; 2가지 한글 타이핑; 내보내기·복원·오프라인.
2. **Android Brave + S Pen 지원 기기**: 탭/가로 이동, 칠판 펜버튼/지우개, 탭 이탈 시 손 터치, PDF 2페이지, 화면 회전·키보드.
3. **원본 보존**: 시험/개인 작업/필기/OCR/초안 JSON 각각 사전 백업 파일 열기 → 테스트용 프로필 복원 → 해시 또는 주요 원본 값 일치.
4. **서비스워커**: 최신 캐시 세대·필수 11/11·선택 캐시, 재방문/오프라인/연결 복구·구형 자산 오염 방지.
5. **시각/기능**: 원안 대비 UI·다크모드·헤더/설정·모바일 탭/스크롤 위치, 배경 GPU 유휴.
6. **배포**: GitHub main SHA = Vercel Production의 git SHA = 사용자 운영 도메인. 앱 설치 EXE/APK/ZIP은 사용자가 실제 요청하지 않으면 만들지 않는다.
7. **검증표**: 기존 28개 사용자 검증 항목 ID 및 과거 기록 보존. 항목별 PASS / FAIL / NOT_RUN, 기기·재현법·증거를 분리 기록.

**배포 규칙:** 일반 git push의 자동 Vercel 배포 비활성 유지, GitHub Actions 자동 실행 0회. 기능을 묶어 최소 커밋으로 올리고 필요할 때 **수동 Production 배포 1회**로 검증한다. CI는 중간 0회/최종 수동 1회 원칙. 출처·정답·개인 데이터를 손대지 않는 회귀 테스트 우선.

## 8. Batch F — AI 여성 TTS는 마지막 (현재 미해결)

**현재 관찰:** 여성 AI 목소리가 문장 중간에서 끊기고, 시작·문항 전환이 느리며, 약 398MB Supertonic 3 모델 준비가 실용적인 기본 음성처럼 동작하지 않는다. 'AI 음성 출력 시작 3/252' 같은 UI 진행 표시를 실제 음성 완주 증거로 삼지 않는다.

**최종 단계 조사·구현 방안 (미확정, 실측 비교 후 선택):**
- **A. 고정 공식 원문 단위 사전 합성/오디오 캐시:** 공식 문항 텍스트·선지를 안정된 문항 ID와 내용 해시로 분할; 선택한 연도/세트에 한해서 사용자 동의 후 캐시; 텍스트와 음성 파일의 버전 일치 검증. 800문항 전체를 사용자 동의 없이 자동 다운로드하지 않는다. 저장량·저작권/라이선스 검토.
- **B. 기기 내 TTS 모델 1회 설치:** 라이선스·배포권한 확인, 버전 SHA256, 용량/기기 RAM/웹 추론 속도·메모리/배터리, 동의형 다운로드, 재방문 재활용·기기별 안전한 폴백.
- **C. 기본 기기 음성 폴백:** 기기 한국어 음성을 기본적으로 빠르게 사용할 수 있게 유지하되, 실제 품질/성별은 OS마다 달라질 수 있음을 안내.
- **공통 재생 제어:** 청크 생성/오디오 버퍼를 분리, 끊김 없는 선행 생성·큐 연결, 문항 중간 재생·북마크·중지/재개, 1.5배/3모드, 백그라운드/화면잠금/연결 해제, 구형 엔진 중복 제거. 정지 후 늦게 재생되는 오디오 금지.
- **검수:** 공식 800문항의 법률용어·숫자·㎡·선지 ①~⑤·전원정답 안내, 40문항 연속 청취, Windows Brave/Edge + Android Brave 실음성 녹음/실측. 자연스러움과 지연의 기기별 PASS를 따로 기록.

**절대 금지:** 모델 준비 UI만 고쳐놓고 'AI TTS 완료' 표시; 실제 캐시 데이터 없는 가상 준비 상태; 미확인 파일을 필수 PWA 캐시에 강제로 포함; 개인 TXT/PDF/메모를 외부로 무단 업로드.

## 9. 작업·완성률·검증 보고 계약

진행표는 각 Phase마다 '계획 수 / 코드 반영 / 정적·모의 PASS / 실제 기기 PASS / 근거 데이터 검수 / 운영 반영'으로 분리한다.

- 코드 반영 비율은 인수 체크리스트 항목을 실제 소스로 연결했을 때만 표시.
