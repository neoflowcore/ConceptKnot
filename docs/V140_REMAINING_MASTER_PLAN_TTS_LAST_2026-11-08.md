# ConceptKnot v140 이후 잔여 개발계획서 v1.1 — P6-B 반응형 개념 그래프 통합

**프로젝트는 ConceptKnot 단독이다. DoCut 개발은 이번 계획에서 제외한다.** 또한 기존 17종 통계·차트의 숫자 검산에 그치지 않고, **그래프·도형을 사용자가 직접 조작하여 직전/현재 상태의 변화와 이론·기출을 함께 학습하는 P6-B 인터랙티브 엔진**을 추가한다. **P6-B는 아직 구현되지 않은 개발 목표**이며 이 계획서의 설명·예시는 완료된 앱 기능이 아니다. 사용자가 AI 여성 음성의 끊김과 지연을 직접 보고했으므로 TTS는 비음성 잔여 과업을 마친 뒤 마지막 단계에서 재설계한다. **이 문서는 다음 채팅의 개발 재개용이며, 계획서 작성 시 앱 기능은 수정하거나 재배포하지 않는다.**

## 7. Batch D-2 — P6-B 인터랙티브 개념 그래프·도형 학습 엔진 (신규 핵심 과업)

> **이 Phase의 목표는 일반 통계 차트 개선이 아니다.** 사용자가 수요·공급곡선의 위치·기울기·점·축을 직접 드래그하면 관련 변수와 균형점이 **실시간으로 재계산**되고, **직전 상태와 지금 상태를 동시에 그리며**, 왜 변화했는지를 이론·비례/반비례·공식 기출 근거와 함께 서술한다. 학습자는 **그림을 관찰하는 사람에서 실험하는 사람**으로 바뀐다. 2026-11-08 기준 계획만 확정; 코드 완료 또는 실기 PASS 아님.

### 7-1. 전체 학습 흐름과 화면 계약

`개념 선택 → 직전 상태 저장 → 그래프/핸들 직접 이동 → 상태 계산 → 이전/현재 중첩 비교 → 조건이 드러나는 자동 설명 → 기본이론·검증된 기출 연결 → 같은 상황을 재현하는 미니퀴즈 → 되돌리기/기록`

- **직관적 조작**: 곡선 전체를 좌우·상하로 이동, 기울기 핸들, 가격·수량 기준점 드래그, 슬라이더와 수치 입력. 드래그 중 움직이는 것이 **곡선 자체(수요/공급의 변화)**인지 **곡선 위 점(수요량/공급량의 변화)**인지 UI에서 모드와 색·패턴으로 명확히 구분한다.
- **전/후 비교**: 이전 곡선·균형점을 옅은 선/점선으로 보존, 현재 곡선은 굵은 실선, 가격·거래량 변화는 축의 화살표·수치 및 부호로 표시. 직전 상태와 초기 기준선 모두 전환 가능.
- **자동 서술**: `무엇을 조작했나 → 어떤 곡선/변수가 움직였나 → 균형가격·균형거래량이 어떻게 변했나 → 다른 조건은 무엇이 고정되었나 → 비례/반비례 또는 인과 해석의 범위 → 기출에서 혼동하기 쉬운 부분` 순서로 짧고 명확하게 생성한다. 근거 없는 서술은 출력하지 않는다.
- **기본이론**: 조작 상태에 연결된 핵심 정의, 수식, 그래프 해석, 혼동 주의점을 카드로 표시. 정오 판단은 수학/규칙 기반으로 하되 기존 공식 해설의 출처 감수 상태를 구분한다.
- **기출 연결**: RECALL_OFFICIAL의 실제 존재하는 문항 ID, 연도·과목·공식 원문 및 검증된 개념 태그가 있는 경우에만 버튼 활성화. 해당 링크가 검증되지 않았다면 **“관련 기출 연결 검토 중”** 표시, 임의 연도·문항 번호나 가짜 해설을 생성하지 않음.
- **저장**: 조작 이력/학습 진행도는 별도 옵트인 영역만 사용. 공식 800문항, OMR, 틀린 문제, 타이핑·S Pen 자료를 덮어쓰지 않으며 안전한 Undo/Redo/Reset 제공.

#### 반응형 레이아웃

- PC/가로 태블릿: 왼쪽 **그래프 약 2/3**, 오른쪽 **자동 설명·기본이론·관련 기출 약 1/3**. 상단 모드 탭, 하단 이전/현재 비교 및 변화 수치. 기존 ConceptKnot 테마·도트·우드브라운을 계승.

### 7-3. 수요·공급 첫 번째 구현의 명시적 계산 규칙

임의 수치를 “공식 기출 사실”로 제공하지 않고 **계산 원리 시연용 가상 시장**임을 표시한다. 기본 선형 예시는 다음과 같다.

```text
수요량 Qd(P) = 120 − 2P + u
공급량 Qs(P) =  20 + 2P + v
P = 가격, Q = 수량, u = 수요 이동 계수, v = 공급 이동 계수
조건: 수요/공급 함수의 기울기는 양의 크기, 외생 이동 제외 모든 조건 일정
균형가격 P* = (120 + u − 20 − v) / (2 + 2)
균형수량 Q* = 120 + u − 2P* = 20 + v + 2P*
기준 상태: u = 0, v = 0 → E0 = (P*=25, Q*=70)
```

- 수요 곡선을 우측 이동(u 증가)하면 공급 일정 하에 가격/거래량이 모두 상승하는지 산출한다.
- 공급 곡선을 우측 이동(v 증가)하면 수요 일정 하에 가격 하락/거래량 상승을 산출한다.
- **가격점만 이동**하면 수요/공급곡선은 그대로 있고 각각의 `Qd(P)`·`Qs(P)`가 달라진다. 임의의 가격에서 관측된 수요량/공급량을 **새 균형 거래량**이라고 오인하지 않는다.
- 수요·공급이 동시에 이동하면 변화의 부호가 조합에 따라 달라진다. 수식·가정 없이 “가격 무조건 상승” 등 단정 금지. 예컨대 양쪽 우측 이동은 거래량 증가하나 가격 변화는 상대 이동폭에 따라 상승/하락/불변이다.
- 곡선의 **이동**은 비가격 요인, 곡선상의 **이동**은 자기 가격 변화라는 구분을 해설에 반영한다. 수요 가격탄력성은 점 예시 `Ed = (dQd/dP)·(P/Qd)`, 공급 `Es = (dQs/dP)·(P/Qs)`로 계산하되 절댓값/부호 및 점·호 개념을 분리. 기울기 그 자체와 탄력성은 다르다.
- 기울기 드래그는 축·피벗·매개변수 고정 조건을 명시하고, “수요량 증가=수요 증가” 같은 잘못된 자연어 요약을 차단한다.
- 음수 가격/수량, 분모 0, 그래프 범위 밖 교차, 수직/수평 등 특수 경우는 안전한 도메인 제한 또는 설명 가능한 “해당 모델에서 계산 불가”로 처리. 원래 개인 학습 자료/공식 시험문제에 영향을 주지 않는다.

#### 실제 조작 예시: 직전 → 현재

**조작 전:** `u=0, v=0`, E0 `(25,70)`. **수요곡선을 오른쪽으로 드래그**하여 `u=20`으로 변경하면 E1 `(30,80)`. 오른쪽 설명 카드에는 다음처럼 표시한다.

> **변경:** 수요곡선 우측 이동(수요 증가), 공급곡선은 고정. **결과:** 균형가격 25→30(+5), 균형거래량 70→80(+10). **이유:** 각 가격에서 더 많은 수량을 구입하려는 수요 변화가 기존 공급곡선과 더 높은 가격·많은 수량에서 교차했다. **혼동주의:** 이는 가격만 변해 같은 수요곡선 위에서 움직인 ‘수요량 증가’와 다르다. **관련 학습:** 부동산학개론 수요·공급의 이동과 균형가격. 공식 기출 링크는 문항 ID 검증 완료 시만 제공한다.

### 7-5. 학습 모드 4종과 도형 확장 계약

1. **자유 조작:** 내가 곡선을 이동/회전/점 선택 → 전후 수치 + 이론 설명 자동 갱신.
2. **개념 미션:** “공급이 일정할 때 수요를 늘리고 균형거래량의 변화를 확인하세요” 제시 → 사용자가 드래그 → 목표 상태 검증 → 왜 그런지 풀이. 이때 답을 먼저 표시하지 않는 학습 옵션 지원.
3. **기출 재현:** 실제 관련 기출의 검증된 조건을 표시하고 사용자가 그래프를 재현. 해당 문항 채점·해설 검수 여부, 출처/기준년도를 명확히 분리. **연결되지 않은 기출문항을 만들어 내지 않는다.**
4. **비교 학습:** 좌우 2개 상태 또는 직전/현재 중첩 표시, 변수·결과 차이/오답 함정 대비. 바뀌지 않은 변수와 바뀐 변수를 항상 표시.

**우선 그래프 주제:** ① 수요·공급 균형 및 곡선 이동 → ② 정비례/반비례 및 점 이동 구별 → ③ 수요·공급 탄력성 → ④ 예산선/무차별곡선 → ⑤ 한계효용·비용곡선 → ⑥ 생산가능곡선·지대/지가·거미집 모형 등 검증 가능한 도식. 각 주제에 동일한 계산기/서술기 API를 적용하지만 **서로 다른 경제학 가정**을 별도 정의하고 모형 간 억지 연결 금지.

### 7-6. 권장 개발 구조·저장 및 완료 판정

- `concept-graph-models`(곡선 수식/제약/단위) + `concept-graph-engine`(순수 계산/상태/히스토리) + `concept-graph-view`(SVG와 드래그 UI) + `concept-graph-explanations`(조건부 서술) + `concept-graph-links`(이론/검증 기출 ID) 구조로 설계. 실제 파일명·모듈은 현재 저장소에 맞춰 최종 결정.
- **단일 상태 객체**를 유일한 진실원천으로 삼아 그래프 좌표·축 숫자·설명·문항 링크가 동시에 바뀌게 한다. 변화 이벤트는 `adjust-demand`, `adjust-supply`, `change-price-point`, `adjust-slope`, `reset`, `undo`, `redo` 등 구분. 화면 픽셀은 수학 좌표로 역변환해 상태 저장.
- 공식 시험/개인 자료와 독립된 저장 버전, 스키마 검증, 100~200단계 이내 히스토리 제한, 크기/범위 제한, 로컬 저장만 기본. AI 서버로 자동 전송하지 않는다.
- **완료율 표기:** P6-B는 B0~B9 10개 과업 분모로 `코드 반영 / 수학 자동테스트 / 내용 출처 감수 / Windows 실기 / Android 실기`를 각각 기록. 현재는 **설계만 확정, 구현 완료율 미측정, 기기 실기 NOT_RUN**. 수학 모의 테스트 12개 PASS만으로 P6-B 전체 완료라 하지 않는다.
- 기존 P6의 17종 정적/통계 차트는 그대로 유지하되, 이 과업을 **P6-B 독립 인터랙티브 학습 엔진**으로 관리한다. 지금까지 있던 그래프를 단순 확대/색상 변경하여 기능 완료로 보고하지 않는다.

## 8. Batch E — 수기검증 및 수동 배포

**수기 검증 필요 시 크게 표시하고 실제 사용자 기기에서 직접 확인한다.**

## 9. Batch F — AI TTS는 반드시 마지막

**현재 사용자 실기에서 중간 끊김·긴 지연 미해결.** 약 398MB Supertonic 모델 관련 버튼·진행률 표시나 다운로드만으로 완료 선언 금지.

- 대안 A: 검증된 공식 기출 TXT를 문항·선지 청크로 나눠 사전 합성/캐시. 문항 ID+내용 해시로 버전 일치, 사용자가 선택한 연도·세트만 다운로드. 800문항 전체 강제 프리캐시 금지.
- 대안 B: 실제 라이선스·배포권한·SHA·메모리/저장량/배터리 실측 후 기기에 AI 여성 음성 모델 1회 설치·재사용.
- 대안 C: 실패 시 한국어 OS 기본 음성으로 즉시 폴백. OS마다 여성 음색 보장 불가.
- 버퍼링·선행 합성·큐 연결, 중간 끊김·문항 건너뜀·늦은 재생 방지. 3개 듣기 모드, 1.5배속, 정지·이어듣기·북마크.
- 공식 800문항의 법률용어·숫자·㎡·①~⑤ 발음, 40문항 이상 연속 듣기, Windows Brave/Edge·Android Brave 실제 소리·지연 측정.
- 개인 필기/TXT/OCR 파일을 외부로 무단 업로드하지 않으며, 사용자 동의 없이 대용량 모델 자동 다운로드 금지.

## 10. 정확한 진행 보고 원칙

- 각 Phase마다 요구 기능 / 코드 연동 / 자동·격리 PASS / 실제 기기 PASS / 콘텐츠 출처 감수 / 운영 반영 **각각 별도 수치**.
- P6-B는 특히 **모델 계산 12개 시나리오·전후 비교·자동 해설·기출 링크 검증·PC/Android 포인터 조작**을 별개 게이트로 기록. 기본 그래프 설계를 앱 구현 완료로 환산하지 않는다.
- 실행하지 않은 실기는 NOT_RUN, 디자인 일치율 미실측은 미측정. 원문 등록률 100%를 전체 개발률이라고 표기하지 않음.
- 완료할 때마다 실제 main SHA, 변경 파일, 테스트 분모, 실패 재현, 다음 작업, 운영 SHA를 체크포인트에 기록.
- 과도한 회귀 검사는 지양하고 기능 완성 후 비파괴 테스트를 묶어서 실시.
