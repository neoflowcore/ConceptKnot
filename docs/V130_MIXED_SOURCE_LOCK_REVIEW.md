# ConceptKnot v130 — 혼합 실전 5세트 고정 원본 검사·오답/미응답/보류 복습

기준일: 2026-11-06. GitHub `main` 복원 기준: v129 `23a345f5b4398f85859d206e8a13cc262e61527f`.

## 1. 현재 의미와 보호 원칙

- 이 기능은 **공식 A형 2016~2025년 문제의 5세트 재배열**이다. 학개론 40 + 민법 40 = 세트별 80문항, 총 400개 서로 다른 문항을 사용한다. 각 연도/과목당 4개씩 고정하며, 시험 시간은 100분이다.
- 실제 공식 PDF·법령·판례의 선지별 의미 감수나 가공된 신규 응용문항 5세트와는 별개이다. 자동 출처 검토 완료/공식 시험 합격 판정을 만들어 내지 않는다.
- CK82의 기존 80문항 원본 시험과 개인 해설·오답 노트·PDF 필기는 변경하지 않는다. CK129 기록은 `ck129-mixed-sessions-v1` 별도 로컬 데이터 키에 저장한다.

## 2. 발견된 문제와 v130 수정

### P3/P5 — 백업의 세트 정체성 위조 방지
- 기존 `validIds`는 80개의 문항 ID 형식/중복 및 과목 40+40만 검사했다. 따라서 백업의 같은 번호들을 임의로 뒤바꾸거나 세트 1에 세트 2의 80문항을 붙여도 세트 1 기록처럼 저장·표시·채점될 가능성이 있었다.
- 신규 `matchesFixedPaper(set,ids)`는 기존 `makeSet(set)`의 **고정 80문항 ID와 순서 전체**가 일치해야 한다.
- `sanitizeSession`·`grade`·병합 복원 검증에 동일 규칙을 적용해 불일치 기록을 조용히 재해석하거나 기존 기록에 덮어쓰지 않는다.
- 데이터 손상 또는 다른 탭의 기록 충돌 시 사용자 기록을 초기화·삭제하지 않는다. 손상 원본 JSON 백업 기능은 그대로 유지한다.
- 향후 세트 배정 알고리즘을 변경하려면 저장된 기존 v129/v130 기록의 80개 ID 매핑을 유지하거나 **명시적 버전 마이그레이션**을 설계해야 한다. 신규 배정표를 과거 기록에 무단 적용하지 않는다.

### P3/P4 — 제출 결과에서 즉시 개인 복습
- 제출 결과에서 전체/오답/미응답/보류 문항 필터를 제공한다. 해당 문항이 없으면 빈 화면 대신 '오답 없음/미응답 없음/보류 표시 없음'을 안내한다.
- 문제별 `근거·개인 풀이` 버튼으로 2021~2025년은 CK78 개인 검토 창, 2016~2020년은 CK76 기출 화면으로 연결한다. 해당 연도의 공식 문제 레코드가 실제 존재하고 일치할 때만 허용한다.
- 필터 선택 후 버튼이 재렌더링되어도 기존 선택 필터에 키보드 포커스를 돌려준다. 필터 선택과 개인 풀이 화면 진입은 기존 점수·답안·정답 JSON을 수정하지 않는다.
- 최근 10회 제출 이력에는 실제 공식 원문 80문항이 준비된 경우에만 과목별 점수·평균·오답·미응답·연습 기준 충족 여부를 표시하고, 로딩 전에는 결과 확인 필요로 표시한다.
- 결과 TXT 내보내기는 현재 탭의 저장 스냅샷과 로컬 저장소가 다른 경우 차단한다. 다른 탭에서 수정한 데이터를 오래된 결과 TXT로 잘못 저장하지 않도록 한다.

### P2/P5 — 키보드와 유휴 시계
- 답 선택·OMR 이동·보류·일시정지/재개 시 화면이 다시 그려져 기존 버튼의 DOM 포커스가 없어지는 문제를 막기 위해, 저장 성공 후 타이핑 가능한 문서 입력을 침범하지 않는 안정된 시험 작업 영역으로 포커스를 복원한다. 숫자키(1~5)와 좌/우 방향키 단축키 연속 입력을 지원한다.
- 다른 브라우저 탭에서 혼합 시험을 일시중지/제출한 저장 이벤트가 도착했는데 현재 작업 영역이 제거된 경우에도 1Hz 타이머를 즉시 동기화해 불필요한 타이머가 남지 않도록 한다.
- 일시정지 상태에서는 기존 안내와 일치하도록 정답뿐 아니라 보류 플래그 변경도 막고 재개한 뒤 허용한다.

## 4. 확인한 검사와 아직 미완료인 검증

**수행 확인된 코드·자료 수준 검사**
- GitHub의 공식 10개년 800문항을 다시 읽고 `makeSet`의 세트별 80문항/학개론·민법 40+40, 연도별 과목마다 4개, 5세트 전체 400개 문항 중복 0, 원문 구조 오류 0을 확인했다.
- 실제 800문항 JSON으로 각 세트의 '공식 인정 정답을 선택한 경우' 학개론·민법 모두 100점, 전부 미응답이면 0점을 모의 채점했다. 배정 400문항에는 전원정답 처리 3건(1·2·5세트 각 1건), 복수정답 1건(2세트)이 포함된다. 이는 **채점 구현 검증**이며 선지의 법령·판례 진위를 감수했다는 뜻이 아니다.
- 격리 JS 모의 실행에서 세트 번호를 속인 문항 배열·같은 문항을 다른 순서로 바꾼 기록의 저장/채점/병합 거부, 일반 세트 시작·답안 저장·일시정지/재개·제출·기록 병합 통과를 확인했다.
- 80개 제출 결과에서 실제 오답 1개·미응답 78개·보류 2개를 각각 필터로 추출하고 개인 근거 화면 연결, 다른 탭 변경 시 TXT 거부, 연결해제된 뷰의 1초 타이머 해제 경로를 격리 실행으로 확인했다.
- JavaScript 문법은 변경 코드에 대해 검사했으나 `node --test` 전체 저장소 테스트를 이 작업에서 실행한 것으로 보고하지 않는다.

**미확인**
- 운영 Vercel 최신 버전 실배포, Android Brave/Windows 실제 브라우저 전체 상호작용, 실물 S Pen 지우개, PDF 두 페이지 필기, TTS 여성 음성/1.5배속/중지·재개 실음성, 실제 GPU/오프라인 네트워크 차단.
- 문제·선지의 법령/판례 전문가 감수, 2016~2020년 공식 해설 개발, 2021~2025년 해설 368건 미작성. 데이터 구조 등록 800/800과 전문가 해설 완성률을 혼동하지 않는다.

## 5. 사용자 수기 실기검증 필수 체크

1. 기존 학습 JSON·PDF 필기·OCR 초안·CK129 혼합 시험 JSON을 각각 백업하고 다운로드된 파일을 직접 열어 저장 여부를 확인한다.
2. 수동 배포한 뒤 Vercel 운영 SHA와 최신 GitHub SHA를 비교한다. 운영 v115라면 v130 기능을 아직 검증할 수 없다.
3. 1~5세트를 각각 시작해 80문항/100분/학개론 40+민법 40 배정과 400문항 중복 없음을 확인한다.
4. 1~5 숫자키 답 선택, 좌·우 방향키, OMR 이동, 중간 일시정지/재개, 브라우저 숨김/복귀 후 남은 시간 및 답안 보존을 확인한다.
5. 제출 결과의 오답·미응답·보류 필터와 개인 풀이 진입을 확인한다. 이전 5개년과 최근 5개년 문항이 올바른 분석 화면으로 이동하는지 확인한다.
6. 두 브라우저 탭에서 혼합 시험 기록을 수정한 뒤 오래된 탭의 TXT 다운로드와 JSON 복원이 데이터를 덮어쓰지 않는지 확인한다.
7. 수동 오프라인 캐시 진단 **필수 11/11 + 활성 SW v130** 및 혼합 실전 선택 자산 **2/2**를 각각 확인하고 비행기 모드 진입·재연결을 검증한다.
8. 모바일 가로 탭 스크롤/커서/다크모드/메인 GPU 일시정지, 한국어 TTS 세 모드, S Pen 물리 버튼 지우개, PDF 두 페이지 필기를 직접 확인한다.
9. 설정에 보존된 **28개 항목 수기 실기검증표**의 PASS/FAIL/미확인/재현 단계와 기기를 직접 기록한 뒤 TXT로 저장한다.
