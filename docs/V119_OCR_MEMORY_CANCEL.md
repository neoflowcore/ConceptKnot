# ConceptKnot v119 · OCR 작업 취소 및 모바일 메모리 안전성

기준 v118 `cf72409fc86c6dc40c12a099c44ba2c6f5f40b62` (2026-11-04). **실제 기기 PASS/배포 선언 아님**. 공식 문제·정답·해설 원문 불변.

## 수정
- 사용자 입력 이미지 OCR 전 파일 형식/12MB 상한과 해상도 상한 **2,400만 원본 화소** 검사. 지원 브라우저의 `createImageBitmap`으로 읽고 최대 **1,800×2,200 및 300만 OCR 화소**의 임시 캔버스로 축소. 원본 비트맵을 `close()`해 메모리 회수 시도.
- `createImageBitmap`이 없는 환경에서는 크기를 검증할 수 없는 원본을 OCR 엔진으로 무작정 전달하지 않고 오류 안내.
- OCR 진행 중 PDF·이미지 버튼과 이미지 선택을 비활성화. **중단/탭 전환/브라우저 숨김** 시 대기 작업 토큰 무효화, 활성 워커 종료 시도, UI 조작 재활성화.
- 중단된 옛 작업의 `createWorker` 응답이 늦게 돌아와도 **신규 워커를 덮어쓰지 않도록** 토큰을 먼저 검사하며, 옛 작업의 `finally`가 새 작업의 실행 상태를 지우지 않도록 처리.
- OCR 데이터 전용 로컬 키 및 v118의 공식 자료 무변경·SHA-256 PDF 필기 보관 정책, 사용자가 직접 클릭할 때만 OCR 실행하는 정책 유지.
- HTML/OFFLINE 서비스워커 캐시 `?v=119`로 갱신. GitHub Actions/EXE/APK/ZIP/자동 운영 배포 없음.

## 코드 검사
`tests/v119-ocr-safety.test.cjs`에 큰 이미지 축소·초대형 원본 차단 및 비트맵 정리·중단 워커 토큰 순서·캐시 일치 확인 4건 정의. 기존 v118 테스트의 자산 기대 버전도 갱신. 소스 구문/격리된 인메모리 검사와 실제 Node/Android Brave/CPU·메모리 실기는 구분해서 보고할 것.

## 🚨 수기 실기검증
1. 먼저 학습 전체 JSON과 PDF 필기 전용 JSON/PDF 백업을 별도로 확보. 기존 브라우저 데이터 초기화 금지.
2. **v119를 수동 배포한 경우에만** Chrome·Android Brave 실제 이미지 OCR 테스트. 2,000px 이미지, 5,000×4,000 JPEG, 2,400만 화소 초과 원본 각각에서 정상·축소·차단 상태와 화면 응답성 확인.
3. OCR 시작 직후 **중단 버튼 연속 클릭**, 브라우저 전환·화면 잠금·탭 이동. 새 작업을 다시 시작해도 옛 작업의 글자나 상태가 덮어쓰지 않아야 함.
4. OCR 결과의 ①~⑤ 분리, 개인 수정·TXT 저장·전체 학습 JSON 복원. 공식 문제·정답·검수 플래그가 변하지 않는지 확인.
5. 오른쪽 PDF 두 페이지 S Pen 필기/지우개, PDF SHA-256 구분, 모바일 탭/설정/TTS/다크모드·GPU 회귀도 수기 확인. 메모리/CPU 절감량 수치 자동 추정 금지.
6. 설정 수기검증표에 기기·브라우저 버전·이미지 해상도·작업 취소 순서·결과를 **PASS/FAIL/미확인**으로 기록. 인메모리 코드 PASS를 실제 기기 PASS로 표시하지 않음.
